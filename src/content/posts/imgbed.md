# 前言

博客写久了，图片往往会成为最先失控的部分：把文件直接放进仓库，会让提交记录越来越重；依赖公共图床，又会担心链接失效、限流或广告。一个相对轻量的方案是把 **Telegram 作为文件存储通道**，再用 **CloudFlare ImgBed** 提供上传、管理与公开访问页面。

这套组合并不等于「无限且永远免费的云盘」。它更适合个人博客、文档插图、项目截图等中低频场景。优点是部署成本低、访问地址可控；代价是需要自己保管密钥、处理升级，并接受第三方服务的规则变化。

> [!NOTE]
> 本文以当前的 CloudFlare ImgBed 为例。项目迭代很快，部署前请优先阅读[官方仓库](https://github.com/MarSeventh/CloudFlare-ImgBed)与其文档中的公告、升级说明和环境变量列表；不要直接照搬旧教程里的配置。

## 一、先理解它是如何工作的

一次上传大致会经过下面这条路径：

```text
浏览器上传图片
      ↓
CloudFlare ImgBed（Pages / Workers）
      ↓
Telegram Bot 将文件发送到指定频道或群组
      ↓
KV / 数据库保存文件索引、配置和管理信息
      ↓
访客通过你的图床域名访问图片
```

Telegram 负责接收文件，Cloudflare 负责运行应用与对外分发，KV 则保存文件记录和系统配置。<span style="color:#2563eb">存储通道和访问域名是两件不同的事</span>：即使文件落在 Telegram，文章中使用的仍然可以是自己的图床域名。

当前项目不仅支持 Telegram，也可接入 R2、S3 兼容存储、Discord、Hugging Face、WebDAV 等后端。若只是第一次搭建，建议先只启用 Telegram；等上传、访问与备份流程都稳定后，再考虑增加其他通道。

## 二、准备清单
开始前，请准备好以下内容：

- 一个 Cloudflare 账号，用于 Pages、Workers 与 KV。
- 一个 GitHub 账号，用来 Fork 源码并触发部署。
- 一个 Telegram 账号，用于创建机器人和存放图片的私有频道或群组。
- 一个不常用但容易记住的后台管理员密码。
- 可选：一个已经托管到 Cloudflare 的自定义域名。

建议创建一个**私有 Telegram 频道**作为图床仓库，而不是直接使用个人聊天窗口。频道里的消息就是原始文件记录，单独存放能避免误删，也便于以后迁移或核对。

## 三、创建 Telegram Bot 与存储频道

### 1. 创建机器人

在 Telegram 中搜索 `@BotFather`，发送 `/newbot`，按提示填写显示名称和用户名。完成后会得到一串 Bot Token，形式类似：

```text
123456789:AAExampleToken_Do_Not_Copy_This
```

这串 Token 相当于机器人的密码。<span style="color:#dc2626">不要把它写进文章、截图、Git 提交记录或公开仓库。</span> 一旦怀疑泄露，应立即在 BotFather 中撤销并生成新的 Token。

### 2. 创建频道并授予权限

新建一个私有频道，将刚创建的机器人添加为管理员。它至少需要能够发送消息或媒体文件；如果没有这项权限，图床页面通常会表现为上传失败。

接下来需要频道（或群组）的 Chat ID。获取方法有多种，最稳妥的是按照项目官方文档推荐的方式查询。完成后，将得到类似 `-100xxxxxxxxxx` 的值。请把 Bot Token 与 Chat ID 暂时保存在可信的密码管理器或本地加密笔记中，稍后填写到图床后台。

> [!TIP]
> 先在频道里手动发送一张测试图片。这样既确认频道可用，也能在后续排障时分辨是 Telegram 配置问题，还是图床应用配置问题。

## 四、部署 CloudFlare ImgBed

### 1. Fork 项目并创建 Pages 项目

打开 [CloudFlare ImgBed 仓库](https://github.com/MarSeventh/CloudFlare-ImgBed)，点击 **Fork**，将代码复制到自己的 GitHub 账号。随后进入 Cloudflare 控制台：

1. 打开 **Workers & Pages**，创建一个新的 Pages 项目。
2. 选择连接 GitHub，并选择刚刚 Fork 的仓库。
3. 保持项目文档推荐的构建设置；不同版本的构建命令可能不同，以仓库最新说明为准。
4. 点击部署，等待 Cloudflare 分配一个 `*.pages.dev` 地址。

部署成功后先访问这个地址。能看到登录页或初始化页面，就说明应用本体已经跑起来了。

### 2. 创建并绑定 KV 命名空间

新版项目将 KV 作为必要组件，用来保存配置与文件索引。进入 Cloudflare 控制台的 **KV** 页面，创建一个新的命名空间，例如：

```text
imgbed-kv
```

回到 Pages 项目的设置，为项目绑定该 KV 命名空间。绑定变量名必须使用项目当前文档指定的名称；名称不匹配时，页面可能能打开，但上传或保存设置会失败。

完成绑定后，重新部署一次项目，让运行时拿到新资源。

### 3. 完成后台初始化

打开图床站点，使用默认入口进入管理后台。首次使用时，应当：

- 修改默认管理员账号或密码；
- 在系统设置中选择 Telegram 作为存储通道；
- 填入 `TG_BOT_TOKEN` 与 `TG_CHAT_ID`；
- 保存设置后上传一张测试图片。

不同版本可能把部分配置放在后台，也可能要求在 Pages 的环境变量中设置。无论采用哪种方式，<span style="color:#7c3aed">密钥都应保存为 Cloudflare Secret 或后台私密配置，而不是写入仓库文件。</span>

## 五、绑定自己的域名

`pages.dev` 地址足以用于测试，但正式写博客时，建议绑定独立子域名，例如：

```text
img.example.com
```

在 Pages 项目的 **Custom domains** 中添加域名。如果主域名已经托管在 Cloudflare，控制台通常可以自动完成 DNS 配置；否则按页面提示添加 CNAME 记录即可。

使用自定义域名有三个实际好处：

- 文章里的图片链接更稳定，不会跟着项目名称变化。
- 将来迁移图床时，可以只改 DNS 或反向代理规则，历史文章不必全部替换。
- 图片地址和个人站点的品牌保持一致。

绑定完成后，用浏览器打开一张已上传图片，确认 HTTPS 证书、图片响应和跨网络访问均正常。

## 六、日常上传与 Markdown 使用

上传成功后，图床通常会提供文件链接或 Markdown 代码。博客文章中直接使用标准 Markdown 即可：

```markdown
![CloudFlare ImgBed 上传界面](https://img.example.com/file/example-image.png)
```

建议在上传时建立清晰的目录或命名规则，例如按 `blog/2026/`、`screenshots/`、`avatars/` 分类。即使系统能自动生成文件名，分类仍会让后续查找、迁移和清理轻松得多。

对于截图类图片，也可以在上传前压缩为 WebP 或 AVIF。图床解决的是「存放与分发」，并不会自动消除大图片带来的加载负担。控制单张图片尺寸，通常比事后优化更省心。

## 七、常见问题排查

### 页面可以打开，但无法上传

依次检查：Bot Token 是否完整、机器人是否在目标频道中、是否被授予发送媒体权限、Chat ID 是否对应正确的频道，以及 KV 是否已经正确绑定。修改配置后，必要时重新部署并重新登录后台。

### 上传成功，但图片链接打不开

先确认是否是域名或 DNS 还未生效；再检查 Cloudflare 的访问策略、防火墙规则和项目配置。若只是在某个网络环境无法访问，也要排除当地网络对 Telegram 相关资源的限制。

### 升级后管理后台异常

不要直接覆盖部署。先阅读项目的 Release、公告和迁移说明，导出后台配置或备份数据，再在测试环境升级。项目已经出现过包含构建方式、数据库与配置迁移的较大版本更新，<span style="color:#d97706">备份应当是升级流程的一部分，而不是出现故障后的补救。</span>

## 八、安全与维护建议

图床看起来只是一个上传页面，实际上同时握着你的站点入口、机器人密钥和文件索引。以下几项值得长期坚持：

1. 使用高强度且唯一的后台密码，不与其他站点共用。
2. 不开放匿名管理入口；如果需要多人上传，优先创建独立账户并最小化权限。
3. 定期导出配置、记录关键版本，并保留原始图片的第二份备份。
4. 及时关注项目公告和 Cloudflare、Telegram 的服务规则变化。
5. 不把违法、侵权、敏感或不适合公开传播的内容上传到公共可访问地址。

**最后要记住：免费服务不是零成本服务。你省下的是服务器账单，但仍需要承担配置、备份和维护的时间成本。对于个人博客而言，这个交换往往很划算——你获得了更可控的图片链接，也更理解每一张图片从上传到被读者看到，究竟经历了什么。**
